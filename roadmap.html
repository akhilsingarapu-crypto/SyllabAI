Before We Start

Prerequisites — Words You'll Hear Often

Don't worry if you've never heard these terms. Every single word is explained below with a real-world analogy. You'll use all of these as you build.

🖼️
Frontend
Everything you see and click on a webpage. The visual face of your app — buttons, text boxes, colors, layout.
Analogy: The front of a restaurant — the menu, tables, decoration. Customers see this.
⚙️
Backend
The invisible engine that runs behind the scenes. It processes your uploads, talks to the AI, reads from the database — you never see it directly.
Analogy: The kitchen of a restaurant. You don't see it, but it does all the real work.
🔑
API (Application Programming Interface)
A way for two programs to talk to each other. Your app sends a request ("answer this question") to Google's AI, and Google sends back a response.
Analogy: A waiter. You tell the waiter what you want (request), waiter goes to kitchen, comes back with food (response). You never go to the kitchen yourself.
🗝️
API Key
A secret password (a long code like AIzaSy...) that proves your app is authorized to use a service. Keep it private — never share it.
Analogy: Your library card. Without it, you can't borrow books (use the AI). If someone steals it, they borrow books on your account.
🗄️
Database
A structured place to store and retrieve data. Instead of saving everything in text files, a database lets you search, sort, and find things instantly.
Analogy: A filing cabinet with labeled folders. You can find any document in seconds instead of searching through a pile.
🧠
LLM (Large Language Model)
The AI brain. A model trained on billions of text documents that can read, understand, and generate human language. Gemini is an LLM. So is ChatGPT.
Analogy: A person who has read every book ever written and can answer any question from memory.
📐
Embeddings (Vectors)
A way to convert text into a list of numbers that represents its meaning. Two sentences with similar meanings get similar numbers — even if they use different words.
Analogy: If you describe "apple" as [red=9, round=8, fruit=10, sweet=7], and "mango" as [red=3, round=6, fruit=10, sweet=9] — the numbers show they're both fruits but different. That's an embedding.
🔍
Vector Database
A special database that stores embeddings (meaning-numbers) and finds similar ones fast. Instead of searching for exact words, it searches for meaning.
Analogy: Google Search — type "large red fruit" and it finds "apple", "watermelon" even if those exact words aren't on the page.
📦
RAG (Retrieval-Augmented Generation)
The technique powering this whole project. Retrieve relevant pieces from your notes → Augment (add them) to your question → Generate an answer using AI. The AI only knows YOUR notes, not random internet facts.
Analogy: Open-book exam. The AI "opens your notes" to find the relevant page, reads it, then answers in its own words.
🖥️
Server
A program that runs in the background, waits for requests, does work, and sends back responses. Your Python code IS the server. It runs on your computer (locally).
Analogy: A call center agent sitting at a desk, waiting for phone calls, helping each caller, then waiting again.
🐍
Python
A programming language. Simple, readable, and THE go-to language for AI/ML work. Your backend will be written in Python. It reads like almost-English.
Analogy: A set of instructions you write, and the computer follows exactly. Python's instructions are especially easy to read.
📦
Library / Package
Pre-written code that someone else built and shared. Instead of writing PDF-reading code yourself, you use a library that already does it. Install with one command.
Analogy: IKEA furniture. Someone already designed the parts. You just assemble them.
💡
Remember: You don't need to memorize these. Come back to this page whenever you see a word you don't recognize. These definitions will make more sense as you build.

How It Actually Works

Data Flow — Step by Step

There are two flows: uploading your notes, and asking questions. Here's exactly what happens inside the app for each.

📤 Flow 1: Uploading Your Notes

You drag-and-drop a PDF or text file onto the webpage

The browser (your HTML frontend) picks up the file and sends it to your Python server.

Frontend → Backend

Python reads and extracts the text

A library called PyMuPDF opens the PDF and pulls out all the words as plain text. For .txt files, Python reads it directly.

Python reads file

Text is chopped into small chunks

We split the text into ~500 word pieces. Why? Because the AI works better with focused, small pieces than one giant wall of text.

Chunker runs

Each chunk is converted to a vector (meaning-numbers)

We send each chunk to Gemini's embedding model. It returns a list of 768 numbers that represents the meaning of that chunk.

Gemini Embedding API

Vectors + original text saved to ChromaDB

ChromaDB stores both the numbers (for searching) and the original text (to show the AI). Your notes are now searchable by meaning.

ChromaDB stores data

💬 Flow 2: Asking a Question

You type a question in the chat box

Example: "What is the difference between mitosis and meiosis?"

Frontend sends question

Your question is also converted to a vector

Same embedding process — your question becomes meaning-numbers so we can compare it to your notes' meaning-numbers.

Gemini Embedding API

ChromaDB finds the most relevant note chunks

It compares your question's numbers to all the stored note numbers. The closest matches = most relevant sections from your notes. Usually top 3–5 chunks.

ChromaDB similarity search

We build a prompt for Gemini

We package: your question + the relevant note chunks + an instruction ("Explain this simply, like I'm a student"). This combined message is called a prompt.

Prompt engineering

Gemini generates an answer

The AI reads your notes + your question and writes a clear explanation. It only uses YOUR notes — not random internet knowledge.

Gemini LLM API

Answer appears in your chat

The answer travels back from Python → HTML frontend → displayed on screen. You can keep asking follow-up questions.

Backend → Frontend
Project Structure

Your Folder Structure

Every file has one job. Here's what you'll create and what goes inside each one.

📁 StudyBuddy-Chatbot/  # Your main project folder (already exists)

  📁 frontend/  # Everything the user SEES
    📄 index.html  # The main webpage
    📄 style.css  # Colors, fonts, layout
    📄 app.js  # Makes buttons work, sends messages

  📁 backend/  # The Python brain
    📄 app.py  # The server — entry point, listens for requests
    📄 ingest.py  # Reads files → chunks → stores in DB
    📄 query.py  # Takes question → finds chunks → asks Gemini
    📄 embedder.py  # Converts text to vectors using Gemini

  📁 uploads/  # Temp folder — files land here when uploaded

  📁 chroma_db/  # Auto-created by ChromaDB — your notes memory lives here

  📄 .env  # 🔐 YOUR API KEY LIVES HERE — never share this file
  📄 requirements.txt  # List of Python packages to install
  📄 roadmap.html  # This file you're reading right now ✓
⚠️
The .env file is sacred. It contains your API key. We'll add it to .gitignore so it never accidentally gets uploaded to GitHub. Never paste your API key directly in any code file.

Build Plan

7 Phases — Start to Finish

We build in phases so you understand each piece before adding the next. No phase is skipped.

1

Environment Setup

Install Python, create project folders, install packages, set up your API key in .env. Run "Hello World" in Python to confirm everything works.

📖 You'll learn: what Python is, what pip is, what environment variables are
2

Frontend — The Chat Interface

Build the webpage: file upload area, chat window, message input. Pure HTML + CSS + JavaScript. No Python yet — just making it look good and work in the browser.

📖 You'll learn: what HTML/CSS/JS actually are, how a browser renders a page
3

Backend — The Python Server

Write the Flask server. Define two routes: /upload (receives files) and /chat (receives questions). Test with a fake response first to verify the connection works.

📖 You'll learn: what a server is, what HTTP routes are, what request/response means
4

Document Ingestion — Reading Your Notes

Wire the upload button to actually process files. Python reads PDFs and text files, splits them into chunks, prints them out so you can see it working.

📖 You'll learn: how to use a Python library, what file I/O is, why chunking matters
5

Embeddings + ChromaDB — The Memory

Connect to Gemini's embedding API. Convert chunks to vectors. Store them in ChromaDB. Test a search — upload a note, then search for a related phrase and see the right chunk come back.

📖 You'll learn: what embeddings are, how similarity search works, what a vector DB does
6

RAG Query Pipeline — The Answering Engine

Connect all the pieces: question → embed → search ChromaDB → build prompt → send to Gemini → return answer. The full RAG loop working end-to-end.

📖 You'll learn: what prompt engineering is, how RAG works in practice, what "context window" means
7

Polish + Personal Tuning

Style the UI to your taste. Add a "Sources" section showing which part of your notes the answer came from. Add a system prompt that tells the AI your learning style. Make it yours.

📖 You'll learn: what a system prompt is, how to customize AI behavior, full-stack thinking
